---
description: Закрыть тему — свести в main, убрать worktree, ветку и вкладку, закрыть якорь
---

Аргумент: `$ARGUMENTS` — id якоря или пусто (тогда берётся якорь текущей ветки).

Порядок. **Ни один шаг не пропускай молча**: если что-то не сделано, скажи об
этом прямо, а не закрывай тему как завершённую.

1. **Проверь, что работа сдана.** Есть `.anchor/done.json` в дереве темы
   (воркер вызвал `worker-done`) и итог в якоре. Маркер со статусом
   `not_done` — тема не готова: прочитай итог и реши, что дальше. Маркер —
   заявление воркера, а не приёмка: проверку прогоняешь сам (шаг 3).

2. **Проверь, что всё закоммичено.** `git status` в каталоге темы. Незакоммиченное
   при удалении worktree исчезает без следа.

3. **Сведи в main.** Это делает только оркестратор, не воркер.

   **Тема сдана PR** (обычный путь для воркеров; тема в двух репозиториях —
   пара PR, фронт + бэк):

   ```bash
   anchor-merge <якорь> <репо-бэка>:<PR> [<репо-фронта>:<PR>]   # в фоне, ждать выхода
   ```

   - пара проверяется вместе, поверх **свежего origin/main** обоих
     репозиториев, во временных деревьях — по гейтам `.anchor/gates` каждого
     репозитория (с `origin/main`, не из PR);
   - допустимы **только известные падения** из `[known]`; новое — на доработку;
   - **строго по одной**: скрипт держит блокировку, второй прогон ждёт.
     Параллельно не запускать и не связывать ожидания поиском строки в логе —
     ждать выхода процесса (05.10.2026 два прогона сорвали друг друга, а
     ожидание сработало по строке прошлого прогона);
   - **squash**, ровно проверенного коммита;
   - **миграция — только после копии базы**: копия → применение →
     `anchor-merge … --migration <имя> --backup <файл копии>`; без копии
     скрипт откажет;
   - ветки **не удаляются, а переименовываются в `merged/…`**.

   Код выхода 1 — не слито, причина в выводе и в `result.json` журнала.
   «СЛИТО ЧАСТИЧНО» (один PR пары влит, второй нет) — разбирать руками и
   сказать человеку сразу.

   **Тема без PR** (локальная ветка своей сессии) — сначала прогони то, что
   проект считает проверкой: тесты, сборка, линтер. Красный результат — не
   повод останавливаться, но повод сказать о нём человеку и спросить,
   сводить ли. Обычный `git merge` в основном дереве может упасть:
   если рабочее дерево грязное и среди путей есть симлинк на каталог, git
   отказывается сохранять состояние — «is beyond a symbolic link». Тогда:

   ```bash
   git worktree add --detach <временный-путь> main
   git -C <временный-путь> merge --no-ff <ветка темы> -m "<сообщение>"
   git merge --ff-only <получившийся коммит>     # уже в основном дереве
   git worktree remove --force <временный-путь>
   ```

   Сообщение слияния пиши по существу: что изменилось и почему, а не «merge branch».

4. **Убери за собой:**
   - `herdr worktree remove` — каталог темы;
   - ветку не удаляй, а переименуй: `git branch -m <ветка> merged/<ветка>`
     (брошенную — `archived/<ветка>`); имя говорит, чем тема кончилась, и
     работа остаётся восстановимой. На сервере это уже сделал `anchor-merge`;
   - `herdr tab close <tab_id>` — вкладку.

   Шаги независимы и падают порознь: git-часть проходит, а вкладка остаётся —
   или наоборот. Поэтому уборку **проверяют, а не считают сделанной**:

   ```bash
   herdr workspace list      # каталога темы нет, а workspace остался — закрой:
   herdr workspace close <workspace_id>
   herdr agent list          # процесс сессии в удалённом каталоге — тоже мусор
   ```

   Осиротевший workspace виден человеку в списке `spaces` и выглядит как живая
   тема, хотя за ним нет ни каталога, ни процесса.

5. **Закрой якорь:** `bd close <id> --reason="<что сделано и чем проверено>"`.
   Причина — не формальность: через полгода это единственное, по чему видно,
   закрыли тему сделанной или бросили.

6. **Если у якоря остались открытые дети** — не закрывай его. Покажи их человеку
   и спроси: доделать, перенести в другую тему или закрыть как ненужные.

Не пушь в `main` без явного разрешения человека, если правила проекта этого
требуют — проверь его CLAUDE.md.
